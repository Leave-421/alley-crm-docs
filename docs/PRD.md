# PRD · 로코리(가제)

> 상태: 초안 (2026-11-23). 제품을 한 장으로 요약한다. 세부는 아래 「문서 지도」의 각 문서가 기준이다.
> 기준: [`plan/v1 결정 정리.md`](plan/v1%20결정%20정리.md). 서비스 이름 로코리(LOCORI)는 시연용 가제다.

## 한 줄

**가게끼리 손님을 나눠 갖는 골목 단위 예약 CRM.** 한 권역의 참여 가게들이 예약 시스템 하나를 같이 쓰고, 확인된 방문 기록으로 다음 가게를 추천하며 함께 마케팅한다.

## 왜

골목 가게들은 같은 손님을 나눠 받지만, 지금 서비스는 모두 가게 한 곳 단위라 손님을 다음 가게로 잇지 못하고, 상인회는 공동마케팅 효과를 숫자로 남기지 못한다. 자세한 내용은 [`01-problem.md`](01-problem.md).

| 돈 | 실제 결제 없음. 예약금 · 소개 수수료 · 정산 · 쿠폰 할인은 가상 잔액과 거래 내역 |
| 데이터 | 실제 상권 공공데이터를 참고한 가상 데이터, 가능한 만큼 크게 |

역할별 기능 목록과 요구사항 86개는 [`03-requirements.md`](03-requirements.md)에 있다.

| 영역 | 들어가는 것 |

| 예약 (RSV) | 신청 · 확정 · 방문 · 취소, 가게 재량 슬롯, 가상 예약금 · 환불, 다음 코스 예약, 지연 입력 |
| 고객 (CUS) | 공유 동의, 손님 식별(회원 계정 · 비회원 전화번호), 가게별 고객 카드 · 등급, 비회원 정보 파기 |
| 추천 (CRS) | 가게를 누르는 즉시 최대 3곳, 같이 간 비율 + 공공데이터 기본값, 배지 · 이유 문구 · 리롤, 오늘의 코스(많이 이어진 3곳 동선) |
| 쿠폰 (CPN) | 회원 전용 추천 쿠폰, 대상 가게별 30일 1회, 다운로드 후 7일 예약기한 |
| 정산 (STL) | 소개 판정, 수수료 4%(받은 가게 → 상인회 공동 기금), 소개 실적, 월 정산 |
| 분석 (ANL) | 손님 흐름 · 권역 동선, 세그먼트, 가게별 성과 비교, 성공 지표 · 쿠폰 지표 |
| 지도 (MAP) | 3D 골목 보드, 업종 필터, Spotlight Focus, Bottom Sheet, 도보 정보 · 외부 지도 길찾기 |
| 알림 (NTF) | 앱 · 웹 안 알림(사장님 실시간 새 예약, 손님 알림함) |
| 계정 · 가게 (AUTH · STO) | 역할별 권한, 상인회 가입 승인, 정산 후 탈퇴 |

**빼는 것**: 캠페인 발송, 노쇼 상태 · 관리 · 이력 · 페널티, 직원 계정, 상인회 추천 코스, 예약 없이 온 방문 기록, 앱 안 길찾기 · GPS, 실제 결제, 상인회 이용료 처리.

## 성공 지표

| 지표 | 정의 |
| --- | --- |
| 코스 제안 수락률 | 추천 후 7일 안에 예약 신청하고 방문 처리까지 된 건수 ÷ 추천 노출 건수 |
| 재방문율 | 60일 안에 다른 날짜에 다시 방문한 비율 (가게 단위 · 권역 단위) |
| 소개 수수료 총액 | 방문 처리된 달 기준 월 정산 합계 |

보조 지표로 가게 클릭 수, 추천 노출 수, 추천 후 예약 전환율, 가게별 보낸 · 받은 손님 수, 사유별 취소율, 쿠폰 지표를 본다. 쿠폰 사용 ≠ 추천 수락 ≠ 소개 ≠ 가게 간 이동이며 각각 따로 센다.

## 지키는 원칙

- **예약 CRM으로 보인다.** 발표는 CRM 뼈대(고객 카드 · 등급 · 세그먼트 · 소개 실적)를 먼저 보여주고, 쿠폰은 추천을 예약 · 방문으로 잇는 선택적 혜택으로만 설명한다.
- **시연은 사장님 · 상인회 중심**이고, 손님 화면은 짧게 보여준다.
- **개인 단위 정보를 드러내지 않는다.** 상인회는 묶음 숫자만, 사장님은 다른 가게 정보 중 '추천으로 왔는지'만, 손님은 흐름 · 매출 데이터를 보지 않는다. 서버 응답에서 지킨다.
- **근거를 밝힌다.** 가중치 · 시간대 가정 · 시뮬레이션 데이터는 팀이 정한 값이라고 발표에서 밝히고, '실제 이동 패턴을 재현했다'고 말하지 않는다.
