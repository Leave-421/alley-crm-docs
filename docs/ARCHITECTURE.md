화면 하나(모바일 웹앱)와 서버 하나다. 실제 결제 · 외부 지도 길찾기 연동은 하지 않는다(NFR-02, FR-MAP-09는 외부 앱으로 넘기기만).

## 인증과 권한

- **세션 쿠키** 방식이다(Spring Security 세션 + CSRF 토큰).
- 역할은 손님(회원) · 사장님 · 상인회다. 서버가 응답마다 역할별 열람 범위를 지킨다(FR-CUS-05, NFR-03).
- 비회원은 계정이 없다. '비회원 예약 조회'(예약번호 + 전화번호)에 성공하면 그 전화번호의 예약만 다룰 수 있는 제한 세션을 준다(FR-AUTH-03).
- 로그인 전 행동은 익명 방문자 ID 쿠키로 기록하고, 식별되면 손님에 잇는다(FR-CRS-07).
- SSE 연결도 같은 세션 쿠키로 인증한다(EventSource는 헤더를 붙일 수 없어서 쿠키 방식을 골랐다).
- 개발할 때는 Vite 개발 서버 프록시로 API를 같은 출처로 붙인다. 배포 구성은 정해지면 적는다.

## 3D 골목 보드

- 3D처럼 보이는 일러스트(예: 아이소메트릭) 위에 가게를 배치한다. 3D 엔진(three.js 등)은 지금은 쓰지 않는다(잠정).
- **바꾸기 쉽게 나눈다.** 가게 좌표 · 업종 · 밝기 상태(Spotlight · 필터) 같은 데이터와 선택 상태는 그리는 방식과 상관없는 층에 두고, 그리는 층(일러스트 + 가게 표시)만 갈아 끼울 수 있게 한다. 방식이 확정돼 바뀌어도 데이터 층과 화면 동작은 그대로 쓴다.
- 같은 컴포넌트를 손님 화면과 사장님 · 상인회 화면이 함께 쓴다(FR-MAP-02).

## 서버 시각

- 자동 거절 · 자동 취소 · 쿠폰 만료 · 리마인드 · 파기는 모두 서버 시각 기준이다(NFR-06).
- 시연에서 시간을 앞당길 수 있게, 서버 코드는 현재 시각을 직접 부르지 않고 바꿔 끼울 수 있는 시계를 통해 읽는다(00-backlog D18).
