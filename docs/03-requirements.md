# 요구사항 정의서

> 상태: **초안** (2026-11-20). 우선순위와 영역 약어는 팀 확인 전이다.
> 기준: [`docs/plan/v1 결정 정리.md`](plan/v1%20결정%20정리.md)와 결정 회의 기록([11-18](reviews/decision-meeting-2026-11-18.md) · [11-19](reviews/decision-meeting-2026-11-19.md) · [11-20](reviews/decision-meeting-2026-11-20.md)). 날짜가 늦은 기록이 우선한다.
> 기록으로 정해지지 않은 부분은 요구사항 문장 끝에 `[Q-번호]`로 표시하고 「열린 질문」에 모았다.

## 읽는 법

- ID: `FR-<영역>-<번호>`, `NFR-<번호>`. 번호는 두 자리이고, 한 번 붙인 ID는 지우지 않고 「제외」로 바꾼다.
- 우선순위: 필수 / 여유 / 제외. **표의 값은 모두 초안**이다(Q-01).
  - 필수: 시연(사장님·상인회 중심) 흐름이 끊기는 기능, CRM 뼈대(고객 카드·등급·세그먼트)
  - 여유: 있으면 좋지만 빠져도 시연 흐름이 이어지는 기능
- 근거 열 약어: 「정리·절 이름」 = v1 결정 정리의 절, `11-18 A1` · `11-19 D4` · `11-20 #9` = 결정 회의 기록의 안건.

## 영역 약어 (초안, Q-02)

`.github/labels.yml`의 영역 라벨 후보에 맞췄다. 커밋 scope는 라벨 이름(area: 뒤 값)을 그대로 쓴다.

| 약어 | 영역 라벨 | 범위 |
| --- | --- | --- |
| AUTH | `area:auth` | 회원 · 로그인 · 역할 |
| MAP | `area:map` | 골목 지도 |
| RSV | `area:reservation` | 예약 · 슬롯 · 예약금 · 방문 처리 |
| STO | `area:store` | 가게 등록 · 승인 · 탈퇴 |
| CUS | `area:customer` | 고객 카드 · 등급 · 공유 동의 · 보관/파기 |
| CRS | `area:course` | 코스 제안 · 상인회 추천 코스 |
| STL | `area:settlement` | 소개 수수료 · 가상 잔액 · 정산 |
| ANL | `area:analytics` | 동선 · 세그먼트 · 성과 비교 · 지표 |
| NTF | `area:notice` | 앱 · 웹 안 알림 |

## 용어

| 용어 | 뜻 | 쓰는 곳 |
| --- | --- | --- |
| 이동 | 한 손님이 **같은 날 연달아** 방문한 두 가게 | 손님 흐름, 골목 동선, 가게 간 '같이 간 비율' |
| 소개 | 코스 제안을 받고 **7일 안에** 제안된 가게를 예약한 건 | 소개 수수료, 소개 실적 |
| 수락 | 소개 예약이 그 가게에서 **방문 처리**까지 된 건 | 코스 제안 수락률 |
| 방문 처리 | 사장님이 손님이 실제로 왔다고 입력하는 것. 예약이 '방문' 상태가 된다 | 수수료 발생, 수락 확정, 방문 횟수 |
| 가상 잔액 | 실제 돈 대신 쓰는 포인트. 거래 내역만 남는다 | 예약금, 소개 수수료, 상인회 기금 |
| 묶음 숫자 | 손님 한 명 단위가 아닌 집계 값. 5명 미만 묶음은 숨긴다 | 상인회 화면 |

- 수수료율 4%의 근거 한 줄, 일러스트 지도 위 동선 표현 (FR-ANL-03)
