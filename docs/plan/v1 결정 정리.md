## 역할별 기능

시연은 사장님·상인회 중심이고, 손님 화면은 짧게 보여준다.

**손님** (회원·비회원)

- 방문할 권역을 고르고 지역명·가게 이름으로 검색
- 3D 골목 지도에서 15곳을 보고, 업종 칩·필터로 탐색
- 가게를 누르면 바로 다음 방문 추천 최대 3곳 확인 (예약 전에도 가능)
- 기준 가게 예약 → 추천 가게를 '다음 코스로 예약'. 추천 가게를 새 기준 가게로 골라 따로 예약도 가능
- 예약 변경·취소, 내 예약에서 시간순 코스 확인
- 가게 사이 도보 거리·예상 시간 확인, 외부 지도 앱으로 길찾기
- 추천 리롤, 거절 사유는 선택사항
- 회원만: 추천 카드에서 쿠폰 다운로드, 예약에 적용, 내 쿠폰 확인
- 위쪽 종 모양 알림함에서 알림 확인
- 다음 예약 30분 전 알림에서 지연 여부와 예상 도착 시간 입력

**사장님**

- 예약 확인·승인/거절 (새 예약은 실시간으로 받고, 예약 변경·취소·지연 입력도 알림으로 받음)
- 예약 가능 시간·자리 관리
- 방문 처리 입력 (이 시점에 소개 수수료와 제안 수락이 확정됨)
- 쿠폰 사용 확인 (방문 처리와 따로)
- 추천 쿠폰 참여 ON/OFF와 혜택 설정
- 고객 카드: 우리 가게 방문 이력, 메모, 손님 등급
- 세그먼트 분석: 익명 집단 데이터만
- 소개 수수료 내역, 소개 실적(보낸 손님 수·받은 손님 수)
- 우리 가게로 들어오고 나가는 손님 흐름

**상인회**

- 권역 전체 손님 동선과 가게별 성과 비교
- 수수료 정산 확인·확정, 공동 기금 내역
- 가게 등록·관리 (가입 승인)
- 가게 간 공유 정보 정책 설정
- 집계 보기: 묶음 숫자만. 사장님보다 넓은 범위(가게별·권역 전체)를 보지만 손님 한 명 단위는 없음

## 손님 정보와 공유

공유 정보는 시스템 안에서 코스 추천과 집계 계산에만 쓰고, 사장님과 상인회 화면에는 개인 단위로 드러나지 않는다.

| 항목 | 결정 |
| --- | --- |
| 손님 식별 | 비회원은 전화번호, 회원은 계정 |
| 입력 | 회원은 회원정보에서 성별·연령대를 자동으로 가져옴. 비회원은 이름·전화번호가 필수이고, 예약 화면의 선택 칸으로 성별·연령대를 받음 |
| 공유 항목 | 이름, 연락처, 인원, 방문 일시, 방문한 가게 목록, 성별·연령대 |
| 동의 | 예약할 때 공유 동의 체크, 동의하지 않으면 이용 불가 |
| 사장님이 보는 것 | 손님이 추천으로 왔는지 여부, 세그먼트는 익명 집단 데이터만, 자기 가게에 적용된 쿠폰 예약·사용 정보. 우리 가게 손님 흐름은 다른 가게가 드러나므로 5명 미만 묶음을 '5명 미만'으로 표시 (세그먼트는 그대로) |
| 상인회가 보는 것 | 묶음 숫자만 (가게별·권역 전체 집계). 5명 미만 묶음은 '5명 미만'으로 표시 |
| 손님이 보는 것 | 흐름·매출 데이터 열람 권한 없음. 회원은 본인 쿠폰 상태만 |
| 고객 카드 | 가게별로 가짐, 상인회는 집계만 |
| 손님 등급 | 신규(1회), 일반(2회), 단골(3회 이상), 이탈 위험(단골인데 60일 넘게 미방문). 모든 가게 같은 기준. 방문 횟수는 그 가게 기준 |
| 세그먼트 기준 | 손님이 이용한 전체 가게 중 특정 가게를 이용한 비율 |
| 보관·파기 | 비회원만 대상. 마지막 방문 후 6개월이 지나면 이름, 전화번호, 사장님 메모, 지연 입력 도착 시간을 지우고 비식별 집계만 남김. 방문 기록이 없는 비회원은 마지막 예약이 취소된 뒤 30일(설정값)에 파기 |
| 공유 정책 설정 | 상인회가 공유 항목을 켜고 끔. 식별에 필요한 이름·연락처는 끌 수 없음 |

## 코스 추천과 예약

가게를 누르는 즉시 다음 방문 추천을 최대 3곳 보여주고, 기준 가게 예약을 먼저 안내한다. 계산식과 설정값 전체는 [`05-policy.md`](../05-policy.md) 「다음 방문 추천」에 있다.

| 항목 | 결정 |
| --- | --- |
| 추천 시점 | 지도에서 가게를 누르는 즉시. 예약하지 않아도 볼 수 있음. 다음 가게 추천 알림도 보냄 |
| 개수 | 최대 3곳, 같은 가게 중복 노출 없음 |
| 후보 | 기준 가게, 예약을 받지 못하는 가게(휴업·중단, 예약 가능 여부 꺼짐), 손님이 이미 같은 날 예약한 가게를 뺌. 같은 업종과 빈 슬롯 없는 가게는 빼지 않음 |
| 기준 | 같이 간 비율이 기본, 성별·연령대는 보조. 같이 간 비율 = A를 방문한 고유 손님 중 같은 날 다음으로 B를 방문한 고유 손님 수 ÷ A를 방문한 고유 손님 수 |
| 순위 | 기대 대비 비율(같이 간 비율 ÷ B의 권역 전체 방문 비중)로 매겨 인기 가게 쏠림을 줄임. 쿠폰 참여 여부는 순위에 쓰지 않음 |
| 데이터가 부족할 때 | 공공데이터 기본값과 실제 기록을 기록 양에 따라 섞음(평활 상수 k = 10). A→B 고유 손님이 5명 미만인 쌍은 기본값만 (아래 참고) |
| 성별·연령대 보조 | 같은 성별·연령대 손님끼리의 비율을 30% 섞음. 정보가 없거나 그 집단 A→B 고유 손님이 5명 미만이면 전체 비율만 |
| 추천 배지 | A→B 고유 손님 5명 이상이고 A 방문 고유 손님이 k명 이상(실제 기록 비중이 절반 이상)이면 '방문 데이터 기반', 그 밖에는 '지역 인기 가게'. 가까운 가게를 방문 기록 기반처럼 표시하지 않음 |
| 제안 이유 문구 | 추천마다 표시. 숫자 없이 근거 종류별 문구로 안내 |
| 리롤·거절 | 리롤하면 다음 순위 3곳, 끝까지 보면 처음으로. 거절 사유는 선택사항. 거절·리롤은 기록만 하고 순위에 반영하지 않음 |
| 업종 필터와의 관계 | 필터는 지도 탐색용. 추천 후보나 순위를 바꾸지 않음 |
| 예약 순서 | 기준 가게 예약을 먼저 안내. 기준 가게 예약 후 추천 가게의 '다음 코스로 예약하기'가 열리고, 겹치지 않는 시간을 제안 |
| 개별 예약 | 추천 가게를 새 기준 가게로 골라 언제든 따로 예약 가능 |
| 코스 구성 | '다음 코스로 예약하기'로 만든 예약만 기준 가게 예약과 묶어 시간순으로 한 코스(따로 한 일반 예약은 묶지 않음). 각 예약은 독립 기록이라 따로 변경·취소. 기준 가게를 취소해도 다음 코스 예약은 자동 취소하지 않고, 코스 묶음은 유지한 채 기준 가게에 '취소됨' 표시 |
| 앞 가게가 늦어질 때 | 다음 예약 30분 전 손님에게 알림 → 손님이 지연 여부와 예상 도착 시간 입력 → 다음 가게에 전달. 예약 시간은 바뀌지 않음 |
| 도보 정보 | 가게 사이 도보 거리·예상 시간 표시. 직선거리를 보행 거리처럼 표시하지 않고, 경로 API가 없으면 확인되지 않았다고 표시 |
| 길찾기 | 네이버지도·카카오맵으로 넘김. 가상 좌표는 실제 길찾기 대신 시연용 미리보기 |

**'이동'과 '소개'는 다른 기준이다.**

- 이동: 같은 손님이 같은 날 연달아 방문하고 두 가게 모두 방문 처리된 것. 손님 흐름, 가게 간 연관도, '같이 간 비율' 계산에 쓴다. 화면에서는 '같은 날 방문이 확인된 참여 가게'로 안내한다.
- 소개: 추천받고 7일 안에 그 가게를 예약한 건. 수수료와 수락률 계산에 쓴다.
- 가게 클릭, 추천 노출, 추천 가게 예약, 방문 처리, 이동은 서로 다른 기록으로 남긴다. 로그인 전 클릭 · 노출은 브라우저의 익명 방문자 ID로 남기고, 같은 브라우저에서 로그인하거나 비회원 예약을 하면 그 손님에 잇는다.

**데이터가 쌓이기 전 기준 (스테레오타입)**

비회원이라 정보가 없거나, 서비스 초기·새 가게처럼 기록이 없을 때는 공공데이터로 기본 추천을 만든다. 근거는 Rich(1979)의 스테레오타입 사용자 모델링과 Burke(2002)의 전환형(switching) 하이브리드 추천이다.

1. 손님 정보 없음: 업종별 매출 규모(매력도) · 거리 · 업종끼리 붙어 있는 정도(CLQ) 각 0.25, 시간대(요일 포함) 0.125를 합친다. 시간대 항은 팀 가정으로 밝히고, 기준 시각은 기준 가게 예약 시각(없으면 현재 시각)이다.
2. 성별·연령대를 앎: 1에 그 성별·연령대의 업종별 매출 비중(0.125)을 더한다.
3. 기록이 쌓임: 실제 기록과 섞어서, 기록이 많아질수록 실제 '같이 간 비율'에 가까워진다.

가중치·k·섞는 비율은 데이터로 추정한 값이 아니라 팀이 정한 설정값이다.

공공데이터는 지역·업종 특성을 보는 데만 쓰고, 외부 이동량을 가게 사이 방문 건수로 바꾸지 않는다. 지표와 논문 근거는 [`docs/research/코스 제안 지표와 근거.md`](../research/코스%20제안%20지표와%20근거.md)에 있다.

| 항목 | 결정 |
| --- | --- |
| 대상 | 회원만 다운로드·적용·사용. 비회원은 추천·일반 예약만 가능하고, 다운로드를 누르면 로그인 안내 후 원래 가게로 돌아옴 |
| 쿠폰 주인 | 추천 카드에 뜬 대상 가게의 혜택 (기준 가게의 혜택이 아님) |
| 발급 | 추천 카드의 '쿠폰 다운로드'를 눌렀을 때만. 가게 클릭·추천 노출로는 발급하지 않음 |
| 30일 제한 | 같은 회원이 같은 대상 가게 쿠폰을 다운로드 시각부터 30일에 1회. 다른 기준 가게에서 같은 가게를 추천받아도 제한 공유. 만료·취소해도 유지. 미사용 적용 쿠폰이 남아 있으면 30일이 지나도 추가 발급 안 함 |
| 7일 예약기한 | 다운로드 시각부터 7×24시간 안에 예약을 신청해야 적용(신청 시각 기준, 거절되면 적용 취소). 적용된 뒤 방문일이 7일을 넘어도 혜택 유지. 기한이 지나면 만료 |
| 예약 화면 | 유효 쿠폰을 자동 선택하되 적용 해제 가능 |
| 상태 | 다운로드됨 → 예약에 적용됨 → 사용 완료, 또는 기간 만료 · 적용 취소. 30일 대기는 계산해서 보여주는 화면 상태 |
| 사용 처리 | 방문 처리와 쿠폰 사용 확인을 사장님이 따로 처리. 방문 처리만으로 사용 완료가 되지 않음 |
| 취소·변경 | 방문 전 취소하면 적용 취소, 다른 예약에 자동 재발급하지 않음. 같은 예약 ID로 날짜만 바꾸면 조건 충족 시 적용 유지 |
| 사장님 설정 | 참여 ON/OFF, 혜택 유형(정액 할인 · 서비스 제공. 정률 할인은 MVP에서 구현하지 않음), 총수량을 정함. 서비스 제공은 환산 금액을 입력해 쿠폰 비용으로 기록(수수료 계산에는 안 씀). 참여 가게만 추천 카드에 '예약 혜택' 배지. 총수량이 다 나가면 배지를 내리고 새 발급 중단. 행사를 꺼도 이미 받은 쿠폰은 유지 |
| 할인 한도 | 정액 할인은 방문 금액까지만. 남는 할인은 사라지고, 할인 후 0원이면 수수료도 0원 |
| 가게 운영 중단·탈퇴 | 영업 상태가 휴업·중단으로 바뀌거나 탈퇴하면 그 가게의 미사용 쿠폰은 적용 취소, 그 가게의 30일 제한 해제. 행사만 끈 경우는 해당하지 않음 |
| 비용 | 혜택을 주는 대상 가게가 부담. 할인 비용과 소개 수수료는 따로 기록 |
| 결제 | 실제 할인 결제 없이 가상 혜택 상태로 시연 |
| 동시 요청 | 같은 회원·가게의 동시 다운로드는 서버에서 한 번만 발급. 총수량에도 같은 처리 |
| 알림 | 만료 임박(선택, 중복 최소화), 쿠폰 사용·만료 상태 안내. 가게를 누를 때마다 쿠폰 팝업을 띄우지 않음 |

쿠폰 사용 완료 ≠ 추천 수락 ≠ 소개 인정 ≠ 가게 간 이동이다. 쿠폰 다운로드 때 회원, 추천 기준 가게, 대상 가게, 추천 ID, 다운로드 시각을 함께 기록하고, 나중에 다른 가게에서 같은 가게를 추천받아도 출처를 바꾸지 않는다.

## 수수료와 정산

손님을 받은 가게가 방문 금액의 4%를 내고 상인회 공동 기금이 받으며, 실제 돈은 움직이지 않는다.

| 항목 | 결정 |
| --- | --- |
| 생기는 경우 | 추천을 받고 7일 안에 그 가게를 예약한 경우 ('소개'). 7일은 첫 추천 노출부터 세고, 다시 노출되거나 쿠폰을 받아도 늘지 않음. 예약 시점은 손님 신청 시각. 쿠폰 예약이라도 이 기간 밖이면 소개 아님. 기준 가게를 방문하지 않아도(취소 포함) 수수료는 생김 |
| 생기는 시점 | 사장님이 방문 처리를 입력할 때 |
| 방문 금액 | 사장님이 방문 처리 때 결제 금액(할인 전)을 입력하고, 시스템이 쿠폰 할인을 뺀 금액에 수수료율 적용. 서비스 제공 쿠폰은 원래 금액 |
| 수수료율 | 4% (설정값) |
| 내는 쪽 | 손님을 받은 가게 |
| 받는 쪽 | 상인회 (공동 기금) |
| 보낸 가게 | 돈은 받지 않고, 보낸 손님 수와 받은 손님 수를 소개 실적으로 보여줌. 보낸 가게는 소개 기간이 살아 있고 방문 처리된 기준 가게 중 추천 가게 예약 전 가장 최근에 그 가게를 추천한 곳. 기준 가게 예약도 방문 처리된 경우만 보낸 손님 수에 셈 |
| 방식 | 가상 잔액·포인트 차감, 거래 내역만 남김 |
| 주기 | 월 정산. 방문 처리된 달 기준이라 방문 전 취소된 건은 자동으로 빠짐. 상인회 정산 화면에 가게별 소개 건 평균 방문 금액을 보여주고, 확정 전에 확인 |
| 상인회 이용료 | 시스템에서 다루지 않고 기획 설명만 |

## 예약 운영

예약 상태는 신청 → 확정 → 방문, 그리고 취소다. 노쇼 상태는 없다. 취소에는 사유(손님 취소 · 가게 거절 · 자동 취소)를 남긴다.

| 항목 | 결정 |
| --- | --- |
| 예약금 | 사장님이 가게별 인원당 금액 설정(0원 가능). 회원은 가상 잔액(가상 충전 버튼)으로, 비회원은 전화번호에 묶은 가상 납부 기록으로 처리 |
| 손님 취소 | 예약 시각 24시간 전까지 100% 환불(항상 보장). 그 뒤에는 가게 취소 마감 전까지 취소 가능하고 예약금 일부 환불(비율 설정값). 마감 뒤에는 취소 불가 |
| 가게 재량 | 취소 마감 시간(예약 시각 24시간 전보다 이르게 잡을 수 없음), 동시에 받는 예약 수, 슬롯 단위, 예약 가능 기간 |
| 사장님 거절 | 취소로 처리, 사유 '가게 거절'. 예약금 100% 환불, 쿠폰 적용 취소. 예약 시각까지 승인이 없는 '신청' 예약도 자동으로 같게 처리 |
| 예약 변경 | 다시 '신청'이 되고 사장님이 재승인. 거절되거나, 원래 시각과 바뀐 시각 중 이른 쪽까지 승인이 없으면 원래 예약 유지 |
| 자동 취소 | 방문 처리도 취소도 없는 확정 예약은 예약일 다음 날 자동 취소. 환불 없음, 쿠폰 적용 취소(30일 제한 유지). 노쇼 상태·이력·페널티는 만들지 않음 |
| 비회원 조회 | 예약 완료 화면의 예약번호 + 전화번호로 '비회원 예약 조회'에서 조회·변경·취소·알림 |
| 상인회 계정 | 권역마다 1개를 초기 데이터로 생성, 가입 화면 없음 |
| 가게 가입 | 상인회가 승인 |
| 가게 탈퇴 | 미정산 수수료를 정산해야 탈퇴, 탈퇴하면 가게는 사라지고 방문 이력은 집계에만 남김 |

## 지도와 화면

| 항목 | 결정 |
| --- | --- |
| 전체 표시 | 권역에 들어가면 15곳이 모두 보이는 전체 지도가 기본. 가게를 화면 밖에 숨기거나 겹치게 두지 않음. '전체 보기'로 복귀 |
| Spotlight Focus | 가게를 누르면 기준 가게 1곳과 추천 가게 최대 3곳만 밝게, 나머지 11곳은 위치를 유지한 채 밝기·채도만 낮춤 (클릭 가능). 색만이 아니라 배지·테두리도 쓰고, 애니메이션 감소 설정을 존중 |
| 업종 탐색 | 상단 빠른 칩(전체·음식점·카페·디저트) + 필터 버튼을 누르면 8개 업종 다중 선택. '전체'는 다른 선택과 배타적. 필터를 적용해도 건물을 지우지 않고 낮은 채도로만 표시. 가게를 고르면 Spotlight가 필터보다 우선 |
| Bottom Sheet | 가게를 누르면 지도 위에 열림. 접힘·중간·전체 3단계. 기준 가게 예약 버튼이 가장 우선. 지도와 선택 상태가 항상 일치 |
| 추천 연결선 | 기준 가게와 추천 가게를 점선으로 잇는 시각화. 실제 보행 경로가 아님 |
| 시연 데이터 표시 | 화면에 시연 데이터임을 표시 |

## 지표와 가상 데이터

| 항목 | 결정 |
| --- | --- |
| 지표: 코스 제안 수락률 | 추천 후 7일 안에 예약하고 방문 처리까지 된 건수 ÷ 추천 노출 건수. 추천 노출은 같은 손님·기준 가게·추천 가게 조합을 첫 노출부터 7일 동안 1건으로 셈 |
| 지표: 재방문율 | 60일 안에 다른 날짜에 다시 방문한 비율. 가게 단위와 권역 단위를 나눔 |
| 지표: 소개 수수료 총액 | 방문 처리된 달 기준 월 정산 합계 |
| 지표: 가게별 성과 비교 | 예약·방문 수(사유별 취소율 포함), 소개 실적(보낸·받은 손님 수, 낸 수수료), 재방문율(가게 단위), 수락률 |
| 추가 분석 지표 | 가게 클릭 수, 추천 노출 수, 추천 후 예약 전환율, 확인된 연계 방문 수, 가게별 보낸·받은 손님 수, 업종별 이동 비율, 시간대별 예약 현황 |
| 쿠폰 지표 | 다운로드 수, 예약 적용률, 만료율, 적용 예약의 방문 완료율, 사용 완료 수. 가게 간 이동의 대체 지표로 쓰지 않음 |
| 가상 데이터 범위 | 15곳, 학기 중 9~11월, 실제와 비슷한 예약 시간 분포 |
| 가상 데이터 패턴 | A: 20대 카페 → 디저트 이동이 많음 · B: 금요일 저녁 주점 예약 집중 · C: 코스 추천 이용자의 재방문율이 높음 (시뮬레이션임을 밝힘) |
| 가상 데이터 취소 | 10% 안팎 (하루 전 취소, 당일 취소). 취소율은 다른 지표에 섞지 않고 따로 계산하며, 전체와 사유별로 나눔 |
| 생성 순서 | 가상 고객 → 예약 → 일부 취소 → 방문 처리(방문 금액 생성) → 같은 날 연속 방문 → 이동 통계 → 추천 결과 → 추천 노출·예약 전환 → 소개·수수료 → 대시보드. 모두 같은 원천 데이터에서 계산 |
| 데이터 구분 | 외부 공개 통계 · 시연용 가상 데이터 · 실제 운영 데이터를 나눠 관리 |
| 시연 | 사장님·상인회 중심, 필요할 때 화면 전환, 손님 화면은 짧게 |

## 미결 사항

아래 항목은 아직 정하지 않았지만, 요구사항을 뽑는 데는 지장이 없다.

| 구분 | 항목 |

| 요구사항 | 우선순위 초안(필수/여유)은 이슈 분배 때 팀과 다시 봄 (03-requirements Q-01) |

| 지도 | 3D 지도 위 동선 표현 |
| 발표 | 수수료율 4%의 근거 한 줄 |
