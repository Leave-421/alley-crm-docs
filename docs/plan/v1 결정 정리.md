## v1에서 빼는 것

팀 의견으로 v1 범위에서 뺐다. 나중에 다시 넣을 수 있다.

- 캠페인: 사장님·상인회 모두 발송 기능 없음
- 쿠폰: 발급·사용 모두 없음
- 노쇼 기능: 노쇼 상태, 노쇼 관리, 노쇼 이력 공유, 노쇼 페널티 없음
- 직원 계정: 사장님 계정만 있음

캠페인 대신 마케팅은 코스 제안, 상인회 추천 코스, 제안 이유 문구가 맡는다.

## 역할별 기능

시연은 사장님·상인회 중심이고, 손님 화면은 짧게 보여준다.

**손님** (회원·비회원)

- 골목 지도에서 가게를 보고 예약
- 예약 변경·취소
- 코스 제안 받기: 제안 이유 문구 표시, 리롤 가능, 거절 사유는 선택사항
- 상인회 추천 코스 보기
- 위쪽 종 모양 알림함에서 알림 확인
- 다음 예약 30분 전 알림에서 지연 여부와 예상 도착 시간 입력

**사장님**

- 예약 확인·승인/거절 (새 예약은 실시간으로 받음)
- 예약 가능 시간·자리 관리
- 방문 처리 입력 (이 시점에 소개 수수료와 제안 수락이 확정됨)
- 고객 카드: 우리 가게 방문 이력, 메모, 손님 등급
- 세그먼트 분석: 익명 집단 데이터만
- 소개 수수료 내역
- 소개 실적: 우리 가게가 보낸 손님 수와 받은 손님 수
- 우리 가게로 들어오고 나가는 손님 흐름

**상인회**

- 골목 전체 손님 동선
- 가게별 성과 비교
- 추천 코스 구성: 가게 2~3곳을 묶어 올리고 제안 이유 문구를 붙임
- 수수료 정산 확인·확정
- 가게 등록·관리 (가입 승인)
- 가게 간 공유 정보 정책 설정
- 집계 보기: 묶음 숫자만. 사장님보다 넓은 범위(가게별·골목 전체)를 보지만 손님 한 명 단위는 없음

## 손님 정보와 공유

공유 정보는 시스템 안에서 코스 제안과 집계 계산에만 쓰고, 사장님과 상인회 화면에는 개인 단위로 드러나지 않는다.

| 항목 | 결정 |
| --- | --- |
| 손님 식별 | 비회원은 전화번호, 회원은 계정 |
| 입력 | 회원은 회원정보에서 성별·연령대를 자동으로 가져옴. 비회원은 이름·전화번호가 필수이고, 예약 화면의 선택 칸으로 성별·연령대를 받음 |
| 공유 항목 | 이름, 연락처, 인원, 방문 일시, 방문한 가게 목록, 성별·연령대 |
| 동의 | 예약할 때 공유 동의 체크, 동의하지 않으면 이용 불가 |
| 사장님이 보는 것 | 손님이 제안으로 왔는지 여부, 세그먼트는 익명 집단 데이터만 |
| 상인회가 보는 것 | 묶음 숫자만 (가게별·골목 전체 집계). 5명 미만인 묶음은 숨김 |
| 손님이 보는 것 | 흐름·매출 데이터 열람 권한 없음 |
| 고객 카드 | 가게별로 가짐, 상인회는 집계만 |
| 손님 등급 | 신규(1회), 일반(2회), 단골(3회 이상), 이탈 위험(단골인데 60일 넘게 미방문). 모든 가게 같은 기준 |
| 세그먼트 기준 | 손님이 이용한 전체 가게 중 특정 가게를 이용한 비율 |
| 보관·파기 | 비회원만 대상. 마지막 방문 후 6개월이 지나면 이름·연락처를 지우고 집계만 남김 |

## 수수료와 정산

손님을 받은 가게가 방문 금액의 4%를 내고 상인회 공동 기금이 받으며, 실제 돈은 움직이지 않는다.

| 항목 | 결정 |
| --- | --- |
| 생기는 경우 | 코스 제안을 받고 7일 안에 그 가게를 예약한 경우 ('소개') |
| 생기는 시점 | 사장님이 방문 처리를 입력할 때 |
| 수수료율 | 4% |
| 내는 쪽 | 손님을 받은 가게 |
| 받는 쪽 | 상인회 (공동 기금) |
| 보낸 가게 | 돈은 받지 않고, 보낸 손님 수와 받은 손님 수를 소개 실적으로 보여줌 |
| 방식 | 가상 잔액·포인트 차감, 거래 내역만 남김 |
| 주기 | 월 정산. 방문 처리된 달 기준이라 방문 전 취소된 건은 자동으로 빠짐 |
| 상인회 이용료 | 시스템에서 다루지 않고 기획 설명만 |

## 예약 운영

예약 상태는 신청 → 확정 → 방문, 그리고 취소다. 노쇼 상태는 없다.

| 항목 | 결정 |
| --- | --- |
| 예약금 | 가상 잔액으로 받음, 하루 전까지 취소하면 100% 환불 |
| 가게 재량 | 취소 마감 시간, 동시에 받는 예약 수, 슬롯 단위, 예약 가능 기간 |
| 가게 가입 | 상인회가 승인 |
| 가게 탈퇴 | 미정산 수수료를 정산해야 탈퇴, 탈퇴하면 가게는 사라지고 방문 이력은 집계에만 남김 |

## 코스 제안

다음 가게를 최대 3곳까지 제안하고 제안 이유 문구를 함께 보여주며, 손님에게 강제하지 않는다.

| 항목 | 결정 |
| --- | --- |
| 개수 | 최대 3곳 |
| 시점 | 예약 완료 직후, 방문 당일 알림, 손님이 지도를 볼 때 |
| 기준 | 섞어서 쓰기: 같이 간 비율이 기본, 성별·연령대는 보조 |
| 데이터가 부족할 때 | 공공데이터 기반 스테레오타입 제안 (아래 참고) |
| 상인회 추천 코스 | 상인회가 가게 2~3곳을 묶어 올리는 코스, 자동 제안과 함께 제공 |
| 거절 | 리롤 가능, 거절 사유는 선택사항 |
| 수락 | 제안받고 7일 안에 예약하고, 그 가게에서 방문 처리까지 된 경우 |
| 앞 가게가 늦어질 때 | 다음 예약 30분 전 손님에게 알림 → 손님이 지연 여부와 예상 도착 시간 입력 → 다음 가게에 전달. 예약 시간은 바뀌지 않음 |

**'이동'과 '소개'는 다른 기준이다.**

- 이동: 같은 날 연달아 간 방문. 손님 흐름, 가게 간 연관도, '같이 간 비율' 계산에 쓴다.
- 소개: 제안받고 7일 안에 예약한 건. 수수료와 수락률 계산에 쓴다.

**데이터가 쌓이기 전 기준 (스테레오타입)**

비회원이라 정보가 없거나, 서비스 초기·새 가게처럼 기록이 없을 때는 공공데이터로 기본 제안을 만든다. 근거는 Rich(1979)의 스테레오타입 사용자 모델링과 Burke(2002)의 전환형(switching) 하이브리드 추천이다.

1. 손님 정보 없음: 예약한 가게 업종, 시간대·요일, 거리로 계산. 업종별 매출 규모(매력도), 업종끼리 붙어 있는 정도(CLQ), 거리를 합친다.
2. 성별·연령대를 앎: 1에 그 성별·연령대의 업종별 매출 비중을 더한다.
3. 기록이 쌓임: 실제 '같이 간 비율'로 넘어간다.

지표와 논문 근거는 [`docs/research/코스 제안 지표와 근거.md`](../research/코스%20제안%20지표와%20근거.md)에 있다.

## 알림, 지표, 가상 데이터, 시연

성공 지표 세 가지의 계산 기준이 모두 정해졌다.

| 항목 | 결정 |
| --- | --- |
| 사장님 알림 | 새 예약을 실시간으로 받음 |
| 손님 알림 위치 | 모든 화면 위쪽의 종 모양 알림함 |
| 알림 종류 | 예약 확정·변경·취소, 리마인드 (30분 전) |
| 지표: 코스 제안 수락률 | 제안받고 7일 안에 예약하고 방문 처리까지 된 비율 |
| 지표: 재방문율 | 60일 안에 같은 가게를 다시 방문한 비율 |
| 지표: 소개 수수료 총액 | 방문 처리된 달 기준 월 정산 합계 |
| 가상 데이터 패턴 | 무작위가 아니라 패턴 2~3개를 심어서, 분석 화면이 찾아내는지 보여줌 |
| 가상 데이터 취소 | 10% 안팎 (하루 전 취소, 당일 취소). 취소율이 다른 지표에 섞이지 않게 따로 계산 |
| 시연 | 사장님·상인회 중심, 필요할 때 화면 전환, 손님 화면은 짧게 |

## 미결 사항

아래 항목은 아직 정하지 않았지만, 요구사항을 뽑는 데는 지장이 없다.

| 구분 | 항목 |
| --- | --- |
| 마케팅 | 상인회의 제안 가중치 조절 기능을 넣을지 (결정 보드 2:2 보류) |
| 코스 제안 | 스테레오타입 기본값에서 실제 기록으로 넘어가는 방식 (기록 N건을 넘으면 전환 vs 기록이 쌓일수록 섞기), 스테레오타입 점수를 합치는 가중치 |
| 가상 데이터 | 심을 패턴 2~3개의 구체 내용, 가상 손님 수, 데이터 기간 (재방문 60일을 보려면 3개월 넘게 필요), 시뮬레이션 데이터 표기 |
| 발표 | 수수료율 4%의 근거 한 줄, 일러스트 지도 위에 동선을 어떻게 그릴지 |
| 기획서 밖 | 서비스 이름 (팀이 따로 정함), 참고할 실제 대학가 상권과 가게 10곳 업종 구성 (데이터 작업 때 고름) |
