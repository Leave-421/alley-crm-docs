# 결정 회의 기록 · 2026-11-23 (2) 열린 질문 정리

> [`03-requirements.md`](../03-requirements.md) 「열린 질문」 중 Q-01을 뺀 항목(Q-02 ~ Q-08, Q-10 ~ Q-25)과, 정리하면서 새로 찾은 빈 곳 3개를 정한 결과다.
> 이 기록이 같은 날의 [`decision-meeting-2026-11-23.md`](decision-meeting-2026-11-23.md)를 포함한 이전 기록보다 우선한다.

## 소개 귀속 · 수수료

| 질문 | 결정 | 이유 |
| --- | --- | --- |
| Q-18 기준 가게 A를 방문하지 않고 A에서 추천받은 B만 방문 | **수수료만 인정.** B는 수수료를 낸다. A의 '보낸 손님 수'에는 같은 추천에서 A 예약도 방문 처리된 경우만 센다 | 수수료는 A가 아니라 상인회 공동 기금이 받으므로 '공동 추천으로 손님을 받은 대가'다. 추천이 가게를 누르는 즉시 뜨기 때문에, A 방문 없이 실적을 주면 손님을 놓친 A의 실적이 오른다 |
| Q-10 같은 B를 여러 기준 가게에서 추천받은 경우 보낸 가게 | 소개 기간(7일)이 살아 있고 방문 처리된 기준 가게 중 **B 예약 전 가장 최근에 B를 추천한 가게** | 손님이 예약을 결심한 시점과 가장 가까움 |
| Q-19 쿠폰 다운로드를 새 소개 시점으로 보나 | **아니오.** 소개 기간은 추천 노출 기준만 쓰고, 쿠폰 다운로드로 늘지 않는다 | |
| Q-20 수수료를 할인 전·후 어느 금액으로 계산하나 | **할인 후 금액** | 할인 비용을 내는 가게가 실제로 받은 금액에만 수수료를 낸다. 서비스 제공 쿠폰은 금액이 바뀌지 않으므로 원래 금액에 수수료가 붙는다 |
| Q-21 기준 가게 예약 취소 시 다음 코스 표시와 소개 귀속 | 귀속은 Q-18을 따른다(B를 방문하면 B는 수수료를 내고 A 실적은 없음). 내 예약에서는 **코스 묶음을 유지하고 A에 '취소됨'을 표시**한다 | |
| Q-07 수수료 계산에 쓰는 방문 금액 | **사장님이 방문 처리 때 결제 금액(쿠폰 할인 전)을 입력**하고, 시스템이 쿠폰 할인을 뺀 금액에 수수료율을 적용한다. 가상 데이터는 금액을 생성한다 | |
| (새 항목) 방문 금액을 낮게 입력할 여지 | **상인회 월 정산 화면에 가게별 소개 건 평균 방문 금액**을 보여주고, 상인회가 확정 전에 확인한다 | 수수료를 내는 가게가 기준 금액을 입력하므로, 낮게 적으면 공동 기금(다른 가게들)이 손해를 본다 |

## 계산식

| 질문 | 결정 |
| --- | --- |
| Q-22 같이 간 비율 | 잠정안 확정: A를 방문한 고유 손님 중 같은 날 다음으로 B를 방문한 고유 손님 수 ÷ A를 방문한 고유 손님 수 |
| Q-22 추천 노출 중복 제거 | 같은 손님 · 같은 기준 가게 · 같은 추천 가게 조합은 **첫 노출부터 7일 동안 1건**으로 센다. 소개 기간 7일도 첫 노출부터 센다(다시 눌러도 기간이 늘지 않음) |

## 추천 쿠폰

| 질문 | 결정 |
| --- | --- |
| Q-24 MVP 혜택 유형 | **정액 할인 + 서비스 제공.** 정률 할인은 MVP에서 구현하지 않는다 |
| (새 항목) 서비스 제공 쿠폰의 비용 기록 | 사장님이 쿠폰을 만들 때 **환산 금액**(예: 4,000원)을 입력하고, 그 금액을 쿠폰 비용으로 기록한다. 수수료 계산에는 쓰지 않는다 |
| Q-23 할인 한도 | 정액 할인은 **방문 금액까지만** 적용한다. 남는 할인은 사라지고, 할인 후 0원이면 수수료도 0원이다 |
| Q-23 행사 수량 | **사장님이 총수량을 설정**한다. 다 나가면 '예약 혜택' 배지를 내리고 새 발급을 멈춘다. 동시 발급 처리(NFR-09)는 총수량에도 적용한다 |
| Q-23 가게 운영 중단 · 탈퇴 | 그 가게의 미사용 쿠폰을 **적용 취소**로 바꾸고, 그 가게의 **30일 제한을 해제**한다 (손님 잘못이 아니므로). '운영 중단'은 가게 영업 상태(FR-STO-02)가 휴업 · 중단으로 바뀌어 예약을 받을 수 없게 된 경우다. 사장님이 쿠폰 행사만 끄는 것은 해당하지 않는다(이미 받은 쿠폰 유지) |
| Q-23 예약 변경 시 재적용 | 기존 규칙 유지 (같은 예약 ID로 날짜만 바꾸면 조건을 만족할 때 적용 유지) |
| Q-25 쿠폰 비용 부담 | 잠정 → **확정.** 혜택을 주는 대상 가게가 부담 |

## 예약 운영

| 질문 | 결정 |
| --- | --- |
| Q-03 사장님 거절 | **취소로 처리**하고 취소 사유를 '가게 거절'로 남긴다. 예약금 100% 환불, 쿠폰 적용 취소 |
| Q-04 하루 전이 지난 뒤 취소 | **가게 취소 마감 전까지 취소할 수 있고 예약금 일부를 환불**한다(비율은 설정값, 예: 50%). 마감 뒤에는 취소할 수 없다. **하루 전까지 100% 환불은 항상 보장**하므로, 가게 취소 마감은 '하루 전'보다 이르게 잡을 수 없다 |
| (새 항목) 예약 시간이 지났는데 방문 처리도 취소도 없는 예약 | **예약일 다음 날 자동 취소**하고 사유를 '자동 취소'로 남긴다. 환불 없음. 적용된 쿠폰은 적용 취소(30일 제한은 유지). 노쇼 상태 · 이력 · 페널티는 만들지 않는다 |
| (새 항목) 취소 사유와 취소율 | 취소 사유를 손님 취소 · 가게 거절 · 자동 취소로 기록한다. 취소율은 **전체와 사유별로 나눠** 보여준다 |
| Q-13 예약 변경 후 재승인 | **재승인 필요.** 변경하면 다시 '신청'이 되고 사장님이 승인한다. 거절되면 원래 예약을 유지한다 |
| Q-13 사장님 알림 | 새 예약에 더해 **예약 변경 · 예약 취소 · 지연 입력**을 알림으로 받는다 |
| Q-05 예약금 금액 | **사장님이 가게별로 인원당 금액을 설정**한다. 0원(예약금 없음)도 가능 |
| Q-06 손님 가상 잔액 | 회원은 **가상 충전 버튼**으로 잔액을 늘리고 거래 내역을 남긴다. 결제 연동 없음 |
| (새 항목) 비회원 예약금 | 계정이 없으므로 **가상 납부 기록**만 남긴다(전화번호에 묶음). 환불도 기록으로 처리 |
| Q-08 비회원 조회 · 변경 · 취소 · 알림 | 예약 완료 화면에서 예약번호를 보여주고, **'비회원 예약 조회'에서 예약번호 + 전화번호**로 들어가 조회 · 변경 · 취소 · 알림을 확인한다 |

## 손님 정보 · 열람 범위

| 질문 | 결정 | 이유 |
| --- | --- | --- |
| Q-11 사장님 화면 5명 미만 숨김 | **우리 가게 손님 흐름(FR-ANL-02)에만 적용**하고, 세그먼트 분석(FR-ANL-01)은 그대로 보여준다 | 흐름에는 다른 가게가 드러나 작은 숫자로 특정 손님의 다른 가게 방문을 알 수 있다. FR-CUS-05('다른 가게 정보는 추천으로 왔는지 여부만')와 맞춘다 |
| Q-12 상인회 공유 정보 정책 설정 | **공유 항목 켜기 · 끄기.** 식별에 필요한 이름 · 연락처는 끌 수 없다 | |
| Q-14 가게별 성과 비교 항목 | **예약 · 방문 수**(사유별 취소율 포함), **소개 실적**(보낸 · 받은 손님 수, 낸 수수료), **재방문율(가게 단위) · 수락률** | |
| Q-15 등급 방문 횟수 범위 | **그 가게 기준** | 고객 카드가 가게별이고, 다른 가게 방문이 드러나지 않는다 |
| Q-16 상인회 계정 | 권역마다 상인회 계정 1개를 **초기 데이터로 미리 만들어 둔다.** 가입 화면 없음 | |
| Q-17 방문 기록이 없는 비회원 파기 | 마지막 예약이 취소된 뒤 **30일**(설정값)이 지나면 파기한다 | 방문하지 않은 사람의 정보는 오래 둘 이유가 적다 |
