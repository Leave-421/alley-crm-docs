## 다음 방문 추천

손님이 지도에서 기준 가게 A를 누르면, 후보 가게마다 점수를 매겨 상위 3곳을 보여준다. 점수는 '같은 날 실제로 이어 방문한 기록'과 '공공데이터 기본값'을 기록 양에 따라 섞은 값이다. 순위에는 인기 보정을 건다.

- 근거 기록: [`11-20`](reviews/decision-meeting-2026-11-20.md) · [`11-23`](reviews/decision-meeting-2026-11-23.md) · [`11-23 (2)`](reviews/decision-meeting-2026-11-23-2.md) · [`11-23 (3)`](reviews/decision-meeting-2026-11-23-3.md)
- 요구사항: FR-CRS-01 ~ 07 · 10
- 지표와 논문 근거: [`research/코스 제안 지표와 근거.md`](research/코스%20제안%20지표와%20근거.md)

### 계산 순서

1. 후보를 고른다.
2. 공공데이터 기본값 점수를 구한다.
3. 실제 기록 점수(기대 대비 비율)를 구한다.
4. 두 점수를 섞는다.
5. 손님의 성별·연령대 집단 점수를 섞는다 (정보가 있을 때).
6. 점수순으로 3곳을 고르고, 배지와 제안 이유 문구를 붙인다.

### 1. 후보

권역의 참여 가게에서 아래 가게를 뺀다.

- 기준 가게 A 자신
- 예약을 받지 못하는 가게: 영업 상태가 휴업·중단이거나, 예약 가능 여부가 꺼진 가게
- 손님이 이미 같은 날 예약한 가게 (회원은 계정, 비회원은 전화번호로 식별될 때)

같은 업종 가게와, 그날 빈 슬롯이 없는 가게는 빼지 않는다. 업종 필터와 쿠폰 참여 여부는 후보와 순위를 바꾸지 않는다. 후보가 3곳보다 적으면 있는 만큼 보여준다.

### 2. 공공데이터 기본값 점수

기본값은 가게가 아니라 업종 단위로 계산한다(거리만 가게 단위). 그래서 특정 가게로 쏠리지 않는다.

| 항 | 무엇을 보나 | 데이터 | 가중치 기본값 |
| --- | --- | --- | --- |
| 매력도 | B 업종의 매출 규모 | 추정매출 당월 매출 | 0.25 |
| 거리 | A와 B 사이가 가까울수록 높음 (Huff 거리 감쇠) | 가상 지도 좌표 | 0.25 |
| 업종 동반 입지 (CLQ) | 실제 상권에서 A 업종 주변에 B 업종이 우연보다 많이 붙어 있는지 | 상가정보 좌표·업종 | 0.25 |
| 시간대 (팀 가정) | 기준 시각의 요일에, A 업종 다음 시간대에 B 업종 매출이 몰리는지 | 추정매출 요일별 · 시간대 6구간 | 0.125 |
| 손님층 | 손님의 성별·연령대에서 B 업종 매출 비중 | 추정매출 성별·연령대 | 0.125 |

- 각 항은 후보들 사이에서 0~1로 맞춘 뒤 가중치를 곱해 더한다. 이 합이 `s0(A,B)`다.
- 손님의 성별·연령대를 모르면 손님층 항을 빼고, 나머지 가중치를 합이 1이 되도록 비율대로 다시 맞춘다.
- 시간대 항의 기준 시각(요일·시간대): 손님이 기준 가게를 예약했으면 그 예약 시각, 아니면 현재 시각.
- 거리는 점수 계산에만 쓴다. 화면에 보행 거리처럼 표시하지 않는다(FR-MAP-08).
- 실제 기록과 섞기 위해 '후보를 고르게 뽑았을 때 대비 몇 배'로 바꾼다.

```
lift0(A,B) = s0(A,B) ÷ (후보 전체 s0의 평균)
```

### 3. 실제 기록 점수 (기대 대비 비율)

'같이 간 비율'은 11-23 (2) Q-22 정의를 따른다. 순위에는 이를 B의 평소 인기로 나눈 값을 쓴다. 'A 손님이 특히 많이 이어 가는 곳'이 뜨고, 어디서나 인기 있는 가게의 쏠림이 줄어든다(Karamshuk 외 2013 전이 비율).

```
n_A      = A를 방문한 고유 손님 수
n_AB     = A 방문 고유 손님 중 같은 날 다음으로 B를 방문한 고유 손님 수
같이 간 비율 p(A→B) = n_AB ÷ n_A
share(B) = B를 방문한 고유 손님 수 ÷ 권역 전체 방문 고유 손님 수
lift1(A,B) = p(A→B) ÷ share(B)
```

`n_AB`가 5명 미만이면 실제 기록을 쓰지 않는다(4단계에서 기본값만 씀).

### 4. 섞기

기록이 적을 때는 기본값에, 많을 때는 실제 기록에 가깝게 섞는다(사전확률 평활).

```
n_AB ≥ 5 이면  L(A,B) = (n_A × lift1 + k × lift0) ÷ (n_A + k)
n_AB < 5 이면  L(A,B) = lift0
```

k = 10이면 A 방문 고유 손님이 10명일 때 실제 기록과 기본값이 반반이다.

### 5. 성별·연령대 집단 점수

손님의 성별·연령대를 알면, 같은 성별·연령대 손님만으로 3~4단계를 다시 계산해 `L_g`를 구하고 섞는다.

```
최종 점수 = (1 − g) × L + g × L_g      (g = 0.3)
```

- 성별·연령대를 모르거나, 그 집단에서 A→B 고유 손님이 5명 미만이면 `최종 점수 = L`.
- 집단 계산의 기본값(`lift0`)은 2단계와 같다.

### 6. 순위 · 배지 · 문구 · 리롤

- **순위**: 최종 점수 내림차순으로 상위 3곳. 같은 가게를 두 번 보여주지 않는다. 동점은 재현되도록 고정된 순서로 정한다.
- **배지**
  - '방문 데이터 기반': `n_AB ≥ 5`이고 `n_A ≥ k` (점수에서 실제 기록 비중이 절반 이상)
  - '지역 인기 가게': 그 밖의 경우. 안내 문구를 함께 보여준다(FR-CRS-10)
- **제안 이유 문구**: 숫자를 보여주지 않는다(손님은 흐름·매출 데이터를 볼 수 없음, FR-CUS-05). 근거 종류별 문구 예시는 아래와 같다. 최종 문구는 화면 작업에서 다듬는다.

  | 근거 | 문구 예시 |
  | --- | --- |
  | 방문 데이터 기반 | 이 가게 손님들이 같은 날 자주 찾는 참여 가게예요 |
  | 기본값 · CLQ가 가장 큼 | 이 상권에서 {A 업종} 가까이 많이 모여 있는 업종이에요 |
  | 기본값 · 시간대가 가장 큼 | 이 시간대에 {A 업종} 다음으로 많이 찾는 업종이에요 |
  | 기본값 · 매력도가 가장 큼 | 이 지역에서 많이 찾는 업종이에요 |
  | 기본값 · 손님층이 가장 큼 | 비슷한 연령대 손님이 많이 찾는 업종이에요 |
  | 기본값 · 거리가 가장 큼 | {A 가게}에서 가까운 참여 가게예요 |

  '가장 큼'은 2단계에서 가중치를 곱한 값이 가장 큰 항이다. 거리 문구는 '지역 인기 가게' 배지와 함께만 쓰고, 방문 기록 기반처럼 표시하지 않는다(FR-CRS-10).
- **리롤**: 다음 순위 3곳(4~6위, 7~9위 …)을 보여주고, 끝까지 보면 1~3위로 돌아간다. 리롤해도 계산 기준은 바뀌지 않는다. 리롤로 보인 가게도 추천 노출로 기록한다(노출 중복 제거는 FR-ANL-06).
- **거절 · 리롤 반영**: 거절 사유와 리롤은 기록만 남기고 순위에는 반영하지 않는다.
- **추천 알림**(FR-CRS-02)도 같은 계산을 쓰고, 기준 시각은 예약 시각이다.

### 설정값

코드에 박지 않는다(NFR-04). 상인회가 화면에서 조절하는 기능은 보류다(11-20 #6).

| 설정 | 기본값 | 근거 |
| --- | --- | --- |
| 기본값 가중치 (매력도 · 거리 · CLQ · 시간대 · 손님층) | 0.25 · 0.25 · 0.25 · 0.125 · 0.125 | 팀이 정한 값. 근거가 강한 항에 무게 |
| 평활 상수 k | 10 | 팀이 정한 값 |
| 성별·연령대 집단 비율 g | 0.3 | 팀이 정한 값 |
| 실제 기록 최소 고유 손님 수 | 5 | '5명 미만' 숨김 규칙과 같은 기준 |
| 거리 지수 β | 미결 | Huff(1963) 거리 감쇠 |
| 추천 개수 | 3 | 11-23 |

### 발표에서 밝힐 것

- 가중치 · k · g는 데이터로 추정한 값이 아니라 팀이 정한 값이다.
- 시간대 항은 '업종마다 시간 패턴이 다르다'는 근거 위에 팀이 세운 가정이다.
- 가상 데이터는 시뮬레이션이라, 실제 기록 점수는 시뮬레이션 입력 가정을 되돌려 보여준다.
